01

Step 1 · Target

Which device are you auditing?

Enter its address and pick the profile for its vendor. The profile decides which commands may run on the device and which policy is selected by default.

02

Step 2 · Credentials · optional

How should it log in?

Only tests that need a session use these. Leave it on “No authentication” to run the checks that work before login.

Credentials are sent only with this scan. Save stores them as plain text in this browser for this host and port; Forget removes them. The server host key isn't pinned yet, so use credentials only on the authorised internal lab network.

03

Step 3 · Tests

What should it check?

The policy sets the thresholds every test is graded against. Medium and high-impact tests stay locked until you approve them at the bottom.

Medium and high impact

These try failed logins on purpose or open several sessions, which can trigger lockouts or alerts on the device.

04

Step 4 · Run and results

Run the scan

Progress streams in live. Results stay in this browser tab until you clear them; export them to share or to keep as a baseline.

What changed since last time?

Load a JSON export from an earlier scan; it is compared with the current results.

05

Step 5 · Compare two devices

Is device B as hardened as device A?

Scans both devices now, with the profile, policy and tests chosen above, and reports every difference of B against A.
